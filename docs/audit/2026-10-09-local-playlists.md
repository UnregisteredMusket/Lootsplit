# Device-local licensed DM playlists

The accepted design adds a Music & Ambience feature to DM Campaign tools and existing desktop feature navigation. It preserves all five primary tabs, player shortcuts, existing automatic menu music/ambience/SFX, themes, campaign/account/financial commands, storage and backups. No server migration, dependency, new content asset or signed APK is included.

## Behavior and data

Three previously credited music files form Exploration, Combat and Tavern starter playlists. DMs can create, rename and delete playlists, reuse/reorder/remove tracks, import files with creator/source/license/permission notes, and delete imported files from the device. Imported credit records are user-supplied, never certification of rights. Bundled attribution and adaptations stay visible, with original sources and the CC BY license link; existing Resources credits remain authoritative.

Imported files and metadata use the separate `lootsplit.local-audio.v1` IndexedDB database, shared among DMs using that device. They never enter campaign commands, exports, account backups, server uploads or player caches. Each import/change/deletion uses one transaction across metadata and files, reading the latest committed library before editing. Limits are 50 MB per file, 200 MB imported audio, 200 tracks and 50 playlists. Corrupt records report an error without replacement; unavailable/full storage leaves the previous library intact. Source links allow only credential-free HTTPS.

One streaming HTML media element plays custom audio, avoiding a decoded RAM cache for long imports. Loading cancels obsolete selections and revokes Blob URLs. Custom playback suppresses the automatic music layer while leaving ambience independent. Pause retains the track position; Stop returns to automatic menu audio. Loop and shuffle are independent; shuffle with loop off plays each track once. Assigned scenes switch playlists only during active playback after a Play gesture. Backgrounding pauses custom music and requires Play to resume; fresh documents never autoplay local playlists. Route navigation keeps playback alive and exposes a small Pause/Play/Stop control.

Audio storage/playback require an account-verified DM owning the active device campaign. Public anonymous pages and guests cannot open it. Sign-in/sign-out identity changes clear in-memory audio immediately; stored files remain on the device. No room is ended or campaign changed by audio lifecycle events.
