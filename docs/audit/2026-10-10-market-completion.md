## Supplier identity, pricing and atomic activity

Property suppliers now use `shopAsking` followed by the existing Charisma adjustment for both direct delivery and manager budget review. This fixes ordinary suppliers ignoring the shop's selling rate while keeping the existing black-market premium and party-purse discount rules. Delivery costs include the agreed fee; the trade receipt contains only the goods' price.

The same canonical transit holding receives the explicitly reviewed commodity identity, or the unique commodity bound to its reviewed property material. The resolver checks the material/unit and rejects conflicting links. A display-name match is never an identity match. A material binding alone does not fabricate exchange activity; disabled economies retain physical identity without recording market transactions.

Explicitly linked purchases create one goods-only shop activity receipt at purchase and link the owner payment to it. Arrival and retry alter shipment custody only. Manager purchases run on a cloned candidate so a caught failure cannot leave money, stock, goods or feedback partly changed. The existing downtime preview includes this activity before preparing its seasonal quote. Finance remaps ledger IDs while retaining the immutable receipt link; receipt IDs are not rewritten after seasonal fingerprinting.

## Complete authoritative reversals

The DM-only `ledger-void` command takes an exact ledger/trade target, canonical original fingerprint and a reason. Local execution and shared command submission use the same helper against a candidate table. Existing ledger Void routes through it. Stale input, invalid authority and unsupported or conflicting records reject before commit.

New exchange receipts retain one canonical whole-lot snapshot plus original treasury and optional storage-owner identity. Both ledger movements link explicitly to the receipt. Reversing a purchase refunds the buyer from that original treasury, returns stock and removes only the exact unchanged lot. Reversing a sale repays the original proceeds, consumes the corresponding exchange stock and restores the exact original lot, including partial-lot metadata and images. Zero-copper transactions remain correctable by their trade receipt. Current funds, safe integer limits, stock/capacity and relevant storage ownership/state are rechecked.

Manager component receipts share an operation ID. The helper reverses the entire operation in reverse execution order or rejects it all. Budgets, wages, postage, campaign dates and future order schedules are not rewound. The UI explains those separate management decisions. Recorded seasons, original receipt contents and archives remain immutable; a new opposite-direction receipt affects the current season. Repeat or lost-response attempts cannot create duplicate goods, payments or corrections.

Ordinary purchases preserve exact purchase metadata in shared commands as well as local storage. Supported reversals restore goods/stock/refunds and linked feedback together. Transport receipts, unsupported shop sales and insufficient legacy evidence produce explicit compensating-transaction guidance. Historical ledger lookup includes only authorized archives, deduplicates identical rows and refuses conflicting/missing money legs. Existing archived ledger clearing is preserved. Legacy shared asset-only void patches for linked trades are rejected without weakening `preserveJournalMetadata` authority.

The optional fields do not change saved format versions. Whole holding bytes are retained rather than rebuilding goods from current commodity definitions. Existing room/request/backup limits still reject oversized changes; no truncation or synthetic fallback receipt is introduced. Player projections remove internal settlement snapshots and manager operation IDs, while retaining only their authorized receipts.

Before/Proposed/Applied remain separate, including historical commodity names/units, stock, quotes, indices, locks and realm conditions. No live campaign values are substituted. DM reversal review retains the entered reason through a rejected or pending command and reports the resulting correction. Players cannot open the reversal action or private seasonal history. Private treasury data is labeled as private instead of falling back to zero; server money checks remain authoritative.
