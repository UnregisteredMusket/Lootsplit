# DM location and shop name import

The user requested region, city, town and shop name imports and selected creation of actual campaign entries. This additive tool also supports areas, using the existing hierarchy and configured-shop editor. Baseline main/live is `b3bfc948563ab2c3636a4bacbe9c407a842e967d`; PR70 and its website publication are complete and must not be repeated. Branch: `feature/market-name-import`.

## Behavior and preservation

Market → Manage regions, cities, towns and areas → Import names accepts a pasted one-name-per-line list, TXT, CSV, TSV and JSON. Simple lists use a selected type and existing parent; structured rows use region/city/town/area/shop columns, create missing parents and reuse matching parents. JSON accepts strings or objects with the same columns. CSV preserves quoted commas, doubled quotes, embedded newlines and CRLF. Up to500 rows/128KB input and1,000 new entries per import are supported; the complete preview is paginated rather than truncated.

The confirmed preview becomes one authorized shared/device command. It rejects missing/invalid parents, ambiguous duplicate names and stale name/ancestry previews before any write. Matching uses normalized name, type and parent location, allowing same-named towns/shops in different regions. Existing shop rates, stock, schedules, images, descriptions, balances and party position remain unchanged. New shops use the standard defaults and start closed with no stock; the normal shop editor provides full configuration. Locations and shops stay in the existing campaign/backup/archived-record model, without a new schema migration or platform-specific storage.

The draft guard protects the source and file-reading operation. Reviewed campaign/account/seat scope is captured before confirmation; a changed context cannot redirect the import. Shared accepted/pending/turn-staged notices and existing queue/retry IDs remain authoritative. Durable receipt tests repeat both the original batch and a new batch with the same command after a lost response, producing exactly one import event and no duplicate shops. Players have no import control and server-side commands reject them.
