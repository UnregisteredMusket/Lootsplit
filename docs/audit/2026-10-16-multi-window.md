## Implementation and preservation

The header's Tabs & windows dialog opens the current screen or a permitted destination in a new tab or separate browser window. Users position windows using OS controls; the app does not request screen-enumeration permission or promise automatic monitor placement. Browsers may block popups or choose their presentation. Descriptive screen titles distinguish tabs. A fresh document still shows the existing title screen. Native Android retains navigation and shows desktop-web guidance. All previous full screens, feature returns, menu controls and themes remain.

Each document pins its campaign ID in session storage before providers open. Database, session, seat, owner, mutation, recovery, notification and local-audio checks use that identity; the legacy localStorage selection remains a compatible default for new documents. An explicit switch changes that window and the device default without redirecting another pinned window's writes. Interrupted campaign deletion still preserves newer registry metadata and the original recovery assertions. A removed pinned non-default campaign fails before database fallback.

Shared synchronization queues on the existing browser Web Lock instead of rejecting a companion window immediately. The bounded wait rechecks the captured campaign before entering; unchanged account/server permissions, atomic IndexedDB commands, stale revisions, immutable command IDs and receipts remain authoritative. Same-origin workspace messages contain only invalidation type/campaign identity, never campaign contents or credentials. Passive reloads emit no invalidation loop. Relevant local/shared views refresh from their canonical source; character and encounter drafts remain protected. Account changes clear other windows' cached identity before rechecking access.

New windows inherit the existing per-tab context/reconnect ticket through the browser's same-origin initial blank document; the opener is removed before internal navigation. Invalid or external destinations fall back to Home, and opening a workspace strips invitation/account-callback/legacy seat-link parameters. Guest campaign contents and pending work remain in each document's memory; the child performs the normal authorized room hydration. Closing a window is not Leave or End session. A second DM window remains DM-private; normal player sessions use actual player invitations in another browser profile/device. The dedicated player presentation described below is separate from those authorized workspaces. Music remains device-local; browser mute is available when only one window should produce sound.
