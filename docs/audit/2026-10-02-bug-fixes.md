# Sequential bug fixes and Android preparation

Baseline: a551e1024f7fd23530f18b63691a763cc2e4a07d. Work follows the six findings in the October 2 bug audit in order. Existing UI structure and styles are preserved.

1. **Older editor data loss and permission enforcement — proved.** Legacy saves merge changed fields into the current full sheet, preserve fields absent from the old view, and reject stale changed fields. Local and server legacy saves enforce player ownership; generic DM patches cannot remove the protection or replace protected stats. DM wallet management remains available. The exact browser reproduction now retains level 9, proficiency 4, temporary HP 7, inspiration, conditions, initiative, Athletics and custom notes after filling Race. Six targeted unit/server tests passed, including stale-edit rejection and valid owner/DM operations. The separate long-name reproduction still failed, as expected before step 5.

2. **Older imported-sheet conversion — proved.** One conversion routine now serves campaign projections and supported account imports. It retains explicit proficiency, hit dice, unambiguous single/multiclass levels and exact skill/save/initiative totals without guessing training ranks. Zero HP is preserved. Changed legacy skill totals retain existing modern training. Four legacy regression tests passed; the browser fixture now displays Fighter 9, level 9, proficiency 4, Athletics +8 and initiative +5. The local roll remained +0 at this checkpoint, confirming that step 3 is a separate defect.

3. **Local dice for older characters — proved.** Local roll transactions now read the saved legacy sheet alongside purse and holdings. The exact browser fixture returns STR `1d20+4`, Athletics `1d20+8` and initiative `1d20+5`, matching its displayed values. The campaign-switch reproduction still fails at this checkpoint and is addressed next.

4. **Campaign switching — proved.** Character selection now resets on campaign/seat context changes and resolves local characters even when account lookup is unavailable. Aborted loads cannot reinsert old data, and editor state is scoped to its campaign/seat. The actual Campaigns → Open reproduction now shows the second campaign's character without the old permission error. The same browser run also passes all legacy display/dice checks.

5. **Inventory validation agreement — proved.** Funds/inventory and character equipment now share lossless ID/name/notes validation, so existing accepted items cannot block an unrelated sheet save. The browser reproduction saves HP 4 successfully with a long item name and no alerts. Eight targeted campaign/server tests passed, including long IDs and notes, local/shared HP saves, and rejection of player attempts to change item quantities or names.

6. **Transferred item metadata — proved.** Local and manual transfers preserve notes, weight, artwork, category and equipped state, matching shared transfers; source ownership IDs are replaced with recipient IDs. Transaction-time item data is used. A related queue bug now preserves all pending transfers instead of replacing the first with the second. The exact failing transfer reproduction now passes. Six targeted tests passed: metadata parity, conserved coins/items, insufficient-stock rejection, shared ownership enforcement, two queued transfers through report export/import, duplicate-report rejection, old-file compatibility, backup persistence and explicit DM approval.
