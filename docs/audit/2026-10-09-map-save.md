# Map save correction — October 9, 2026

## Reproduction and correction

The user reported that importing a map could not be saved. A deterministic desktop browser reproduction held actual image decoding, selected a PNG first, then entered a name, location and sharing preference while decoding was in progress. When processing finished, the old implementation replaced the current draft with the pre-upload draft: the name became empty, the location and sharing choice reverted, and the required name field prevented Save. The same captured-draft pattern existed in asynchronous location-label recognition.

Image import and OCR now update the latest draft through functional state updates. Name, location, sharing and anchor edits are retained. Save waits for processing without locking the metadata fields; a visible status explains preparation and readiness. Missing images and whitespace-only names receive actionable messages, with the draft retained. Existing image size limits, reviewed anchors, room permissions, optimistic/stale command checks and retry receipts remain in force. There is no schema, migration, dependency or APK change.

The complete browser audit keeps its earlier offline map/OCR, manual anchors, live markers, wheel/pinch/drag, NPC inventory/dialogue, barter, vendor premium and session-time/rest scenarios. It adds edits during delayed image decoding and OCR, save readiness, missing-image recovery, saved-map edit/reload preservation, and a separate real shared-room import/edit/reload flow at both 1280 and 390 pixels. Reload waits for the editor to close and, for shared writes, the Saved to room status; merely displaying an optimistic map is insufficient evidence of persistence.
