## Automatically filled deed image

A property purchase creates one inventory holding with a deed attachment and a linked purchase receipt in the same atomic transaction. The deed template is an original deterministic SVG image populated from authoritative purchase data: property, location path, original buyer, current holder, actual discounted payment, quantity, campaign day, purchase date, transaction ID and deed ID. All supplied text is escaped; the image has no remote assets or executable supplied markup. Rendering from validated deed metadata allows the image to appear on every authorized device without relying on a client upload. It is not a second inventory asset and never doubles the property's valuation.

The existing Give action moves the lot and its deed together. A transferred deed receives its own ID, the recipient's name and a transfer receipt, retaining the original transaction/buyer/payment/location. Partial lots keep distinct source and recipient deeds with their current quantities. A full sale removes the holding and inventory deed; a partial sale retains the remaining quantity. Original receipts and archived images remain historical records. There is no separate freely duplicable paper item, barter service, bargaining UI or new trading engine.

The property thumbnail opens the full deed image from inventory, owned property management and campaign character inventory. Its transfer link opens the existing Give dialog. Shared player recipients use the current campaign character roster instead of an empty retired offline roster. Existing shared public purse/ledger behavior is retained; property holdings and listing availability follow the authorized projection so unrelated location references cannot invalidate guest views.
