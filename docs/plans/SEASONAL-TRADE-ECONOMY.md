# Campaign trade economies

Authorized implementation follows the October 9 design: separate campaign economies, regional exchanges, Classic/Automatic modes, stable seasonal bid/ask quotes, recorded backend rolls, transactions affecting the next season, settlement through explicitly approved end-of-session downtime and manual DM override. The website publication authorization persists; no new APK is requested.

- Store optional economy state in the existing campaign journal, with stable commodity IDs, units and optional existing material-key bindings. Old saves remain inactive and readable. Each exchange uses canonical location IDs and an existing or explicitly created non-party treasury purse. Purchases and sales transfer existing coins atomically, with finite exchange stock and treasury cash; there is no second player wallet.
- Classic preserves DM prices, supply/demand and stock. Automatic calculates the next season from existing realm settings once, bounded DM policy, immutable d100 draws and that season's recorded purchases/sales. Current-season prices stay fixed until a recorded DM override. The existing Winter/Spring/Summer/Harvest/Autumn calendar remains authoritative.
- An explicit Advance economy season selection in a stored downtime plan advances one season on approval, regardless of the number of downtime days. Clock-only Session Time advances do not settle the economy. Keep the existing approve-and-start-next-session path; add approve-and-end-recorded-session/approve-between-sessions paths. Manual season preview/approval leaves campaign days unchanged.
- Persist automatic draws per upcoming epoch on the authoritative shared server (local crypto for Local Mode). Preparing, cancelling, changing inputs, reloading or retrying the same epoch reuses its draws. Stored quote approval rechecks the whole relevant campaign state; stale previews cannot commit. Full DM overrides are separate recorded actions and retain original draws, receipts and history.
- Players trade only from assigned purses, at the appropriate existing location, using carried goods or authorized property stores. Reserved/in-transit goods, inaccessible stores and unapproved withdrawals remain blocked. Purchases can go directly into an accessible local store. Material-bound production/gathering outputs are recognized by stable material key, never guessed from names; construction reservations retain those keys.
- Explicit shop-stock commodity/exchange bindings let existing ordinary purchases/sales contribute seasonal activity while preserving each shop's configured prices, quantities and behavior. Do not globally reprice custom shops or apply inflation twice.
- Property managers and postal instructions can place bounded buy/sell orders through the existing property-day preview, budget and letter mechanisms. They use the property owner's purse, the property's actual location and canonical goods, current exchange stock/cash and explicit price limits. Letters confer no remote carried-item access. Approved property activity feeds the same seasonal quote.
- DM controls activation, mode, commodity definitions, exchange locations/visibility, treasury funding, stock, prices, supply/demand, bounded automatic policy, manual season preview/approval/cancel and recorded override reasons. Retire referenced definitions instead of breaking inventory/history. Player projections hide internal policies/draws/previews and other characters' transactions; authorized quotes and own receipts remain visible.
- UI uses the current parchment/iron themes, existing Market and Property entry points, a feature screen and responsive cards/controls. Keep all six primary tabs, existing finance editors and navigation. Update Help, import guidance/sample where applicable and the feature inventory.
- Verify economic conservation, finite capacity, permissions, campaign isolation, stable unit identity, stale/lost-response receipts, immutable roll reuse, Classic overrides, Automatic feedback, property/manager/post integration, all session approval paths, clock separation and backup/archive/privacy preservation. Add a complete desktop/mobile browser audit in development and packaged Worker gates. Preserve every prior scenario and account60s/170s/two-worker/zero-retry limits.

Numerical defaults are editable game settings, not official D&D prices or rules. Default automatic hardship changes shortage/roads only; war/plague remain DM-controlled unless explicitly enabled. Default treasury funding is zero and no economy activates on import/load. Existing campaign money limits, room size checks, permission checks and release gates remain.
