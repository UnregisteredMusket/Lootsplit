# Maps, people, barter and session time

These features use the same campaign, room permissions, location hierarchy, purses, inventory, property deeds and campaign clock as Market and Property Management. Existing saves remain readable. Shared map raster images are deduplicated in campaign-private D1 rows by additive migration `0012_campaign_room_images.sql`, outside the single room JSON row; no public image endpoint is added. Room writes and image inserts share the same atomic revision-checked batch. Device/shared exports hydrate full original raster data, including archived snapshots; referenced images remain available after room closure. Existing cloud recovery-size limits still refuse an oversized complete copy before deleting a room, so download a complete device export when needed. The sixth main tab is **Maps**; all five earlier tabs remain.

## Maps

Map categories now include Regional, City, Dungeon, Property, Wilderness, Battle, Ship and Other, with a type filter. Property/ship maps can link an existing holding. **Move party freely** places the party without a listed location and records Roads, Wilderness with a biome, or another travel environment. Travelling closes located shops/listings; selecting a listed party location ends free placement. Private-map party coordinates remain private.

**Combat grid settings** enables configurable columns/rows, alignment, diagonal measurement and tile scale (5 ft by default). In tile mode, the DM places canonical character/ship tokens or imports saved encounter roster tokens, then moves them by tapping a tile or entering coordinates. Players see shared tokens/grid; secret tokens and encounter statistics stay private. The encounter tracker retains turns, HP, conditions and loot. Ship moves carry placed aboard tokens together, while mapped voyage markers follow existing approved downtime. See the complete [map and tile guide](MAP-TILES.md).

DMs import PNG, JPEG or WebP maps, name them and optionally select their existing region, city/town or area. Import multiple maps for world, regional and local views; the last accessible map and camera return by default, with permitted active-scene/location fallbacks. Original uploads can be up to 20 MB / 64 megapixels; the shared raster is compressed to at most 2400 pixels on the long edge and 500,000 data-URL characters. If a map cannot fit, split it into regional maps. No SVG scripts or external image URLs are accepted. Keep original files for future re-import.

You can enter or change the name, location and sharing choice while the image is being prepared or its labels are being read. Those edits are retained. **Save map** becomes available when processing finishes; review the preview and details, then save. A missing or invalid image shows an explanation and keeps the draft open so you can choose another file.

Choose **Read location labels** to run the already-bundled English OCR on the device. It matches whole, unambiguous existing location names and suggests normalized positions. Review the image and anchors before saving. Duplicate names, stylized labels, non-English text and unreadable scans need manual anchors: **Link location**, tap the image, choose the existing location, then save. The tool does not invent places, claim geometric accuracy or move the party during import. Replacing the image clears its old anchors. Anchors can be removed in Edit map and repositioned through Link location.

The party marker follows Market's selected party location. If an area has no anchor, its nearest anchored ancestor supplies the position. If no ancestor is anchored, the screen says the party is unplaced. **Move party here** uses the same DM location command as Market. Properties, shops, permitted nearby NPCs and designated post offices are attached to location anchors and listed in the map register; compact, screen-sized icons group each record type at its anchor; counts appear at the upper right when multiple records of that type share a point. Player maps include only their owned/accessible property records and visible vendors/NPCs. A shipment stays associated with its existing property's records; this is not a simulated moving route.

**Place marker** adds a named point and description live. A marker can be shared or DM-only; Remove marker removes it in the shared room. Maps themselves may be DM-only. Hiding a marker alone does not hide the image pixels. Configure Exploration & lighting for protected fog/vision; players receive only their permitted baked view when concealment is active. Secret marker text is omitted from player responses, archives and public change notices.

Drag with a mouse or finger to pan. Scroll-wheel and two-finger pinch zoom around their focus; +/− buttons, arrow keys and Home provide alternatives. Fit map restores its fitted view. Coordinates are relative to the image and remain stable when its viewport changes. Viewport zoom/pan is local to each reader, while the image, anchors and markers use authoritative room commands. Turn-based changes follow the existing turn queue; Live changes arrive on the existing room sync.

**Filters** independently show or hide locations, markers, characters/NPCs, shops, black markets, properties, post offices and the party. Hide all reveals the map image alone; Show all restores every permitted category. Tap an icon to open its names, details and existing record links. The complete Map register stays available. Filters and map viewport choices affect only your view.

**Ping** toggles point selection for DMs and players in an active room, including outside their turn. Choose red, amber, green, blue or violet and tap/click the image. Everyone viewing the same shared map in that room sees the glow for five seconds, then it expires. Dragging or pinching does not send a ping. Keyboard users can pan the center crosshair to a point and press Enter/Space; Escape stops ping mode. Offline DMs can preview a local ping. Between-session view-only rooms require Resume play before sending pings. Private maps cannot send signals to players. Signals use additive migration `0014_campaign_map_pings.sql`, expire on server time, and do not enter campaign commands, turns, financial records, session archives, device saves or campaign exports. Expired rows are removed during signal access; full database recovery copies may contain expired rows, which can never be replayed.

**Maps** opens directly as an edge-to-edge workspace. The floating search finds accessible maps and records. The hotbar provides frequent play tools; Settings holds map import/edit, categories, filters, linked scenes, grid/access/camera controls and optional player display. Panels overlay the canvas and scroll internally. Close tool options keeps the selected tool active; Escape closes a panel or cancels a tool. The upper-left menu reaches all six destinations, and Back to Lootsplit returns Home. Personal map/camera state survives route changes, refresh and rotation without moving the party or changing the active player scene. Import/edit retains draft guards and in-progress image/OCR work; use Close editor to leave. Browser address bars may remain, but Maps does not depend on native fullscreen permission.

## Non-party NPCs

Open **Market → People & NPCs**. DMs create/import location NPCs with name, description, portrait, starting funds and canonical inventory. They remain outside party counts, player character selection and party wealth. Presence requires a known selected party location in the NPC's city/region/area path. Hiding or moving an NPC removes it from ordinary player responses. Archive an NPC by clearing visibility; its inventory, funds and history are retained.

The DM configures stock and funds and speaks for the NPC by default. Optionally assign an existing player character as controller: that character's authorized player may respond as the NPC and decide NPC trades. This delegates dialogue and consent, not configuration or unrestricted wallet access. Conversation threads are between a party character and that NPC and are visible only to that character's player, the DM and the NPC's configured controller. NPC sheets are private by default for location NPCs; the DM can share a read-only sheet separately from its visible record. Existing fund/inventory permissions remain authoritative. NPC balances are private to the DM and controller; the DM's **Party companion funds** setting (default off) lets party players read the coins and ledger lines of visible NPCs travelling with the party, read-only. NPC replies are human-controlled; no automated dialogue service is added.

Import **strict UTF-8 JSON** with `format: "lootsplit.npcs"`, `schemaVersion: 1`, and a nonempty `npcs` array (up to 100 records per import, 500 total). Each record requires `name`, `description`, `locationId` and optionally `visible` (true), `barterAllowed` (false), `controllerPurseId` (null), `portrait`, `copper` (0), and `inventory` ([]). Each inventory entry requires `name`, positive integer `quantity`, nonnegative integer `unitCopper`, `notes`; `category` and compressed raster `image` are optional. All prices are whole copper. Location/controller IDs must already exist in this campaign. NPC and item IDs are generated, and imports create new records; they never overwrite existing NPCs or move the party. Review the preview before committing; a changed campaign requires another review. An invalid record rejects the entire import. The downloadable sample uses fictional names/values and placeholder location IDs that must be replaced. The JSON Schema validates structure; the authoritative command also validates references, limits and permissions.

## Trading and barter

Open **Market → Trading & Barter**. Offer any carried canonical item lots, goods, property deeds or coins to another party player or a nearby NPC configured with **Bartering allowed**. Party NPCs retain their earlier role; location-NPC bartering is separately configured. An offer may ask for coins or visible NPC goods. Another player's private inventory is not displayed: that player adds their goods in a counteroffer. Counteroffers reverse the recipient; only the current recipient can accept or decline, and a participant may cancel. The DM can act for either side, including NPCs.

Choose **New barter offer**, then select the offering account and other participant. Their existing portraits appear when available. Search the inventories or choose a category; tap a good/deed to add it to the appropriate offer tray, then set its quantity. **Show more** exposes additional lots, and search covers the entire available inventory. Removing a tray entry or tapping its selected inventory tile removes that contribution. Search/category changes retain the offer. Coin contributions are entered as whole copper, with a readable gold/silver/copper equivalent. Recorded offer values use saved item values and coins; they do not determine fairness or impose a sale price. Review both trays and the note, then send the offer/counteroffer. Pending offers and history retain the same visual item/deed summaries. On phones the two sides stack; light, dark and custom themes retain their existing colors.

Each acceptance rechecks participants, NPC presence/bartering permission, exact lot contents/quantity, custody, property obligations and each side's gross coin contribution. One atomic command exchanges both sides; retries use existing room content receipts and cannot repeat an exchange. No goods are reserved by merely proposing an offer. Spending, moving or editing an offered lot makes the old offer stale and requires a fresh offer. All participants can review pending offers and retained decision history; unrelated players cannot see them. Existing Give remains available.

Services, stored/in-transit/reserved lots and properties with active contents, projects, staff, tenants, financial agreements, orders or arrears cannot be bartered until resolved. Use Property Management's explicit DM handover when obligations must accompany an ownership change. A clean deed transfer updates its owner/image information, retains the original purchase receipt and removes the old owner's transferred lot. No second deed inventory asset or duplicate wealth is created.

### NPCs who barter on their own

NPCs with **Bartering allowed** and no player controller also answer offers in a conversation under **View & interact**: numbered replies show the Charisma (Persuasion) DC and odds, the room server rolls, and the NPC accepts, counters or refuses in its own (DM-editable) voice. The DM's **NPC barter rules** choose DM decides (default), Server rolls, DM confirms, or Automatic. The trading table above is unchanged and remains the flow for controlled NPCs. See [NPC-BARTER.md](NPC-BARTER.md).

## Black market

DMs use the Market **Black market** toggle during play to reveal or hide designated vendors. In a shop, open **Black-market vendor rules**, enable the flag and set a premium greater than 1 (default 1.5). Configure names, goods, quantities, rarities, illegal-goods descriptions, locations and schedules through the normal shop/stock tools. The premium multiplies the ordinary asking price before its existing Charisma adjustment. Finite/unlimited stock and ordinary receipts remain unchanged.

Hidden vendors/stock are absent from player projections. The server and local transaction paths recheck visibility, current location and closure at purchase/sale time, including stale queued actions. Property supplier orders also honor hidden-vendor availability and premiums while retaining their existing authorized remote delivery rules. The DM still sees and edits hidden vendors. Toggling does not open a closed shop or move the party. No fixed illegal-item catalog or real-world rules are imposed.

## Session time

DMs open **Session Time** from Market or Desk's session tools during an active recorded play session. Advance an integer 1–24 hours per action; repeat for longer journeys. Review the new clock, finance/stock changes and property work before approving. The same finance clock stores an optional minute-of-day remainder; old saves start at midnight. Crossing a campaign day settles existing recurring finances, shop schedules, postal/delivery/manager orders once. Partial-day advances do not repeatedly collect rents or arrears. Existing between-session downtime remains available; approve/cancel its pending quote before advancing time.

Optionally award no rest, a short rest or a long rest to selected party characters. The DM decides whether the time qualifies under the table's rules. Short rest restores configured short-rest resources. Long rest restores HP, death saves, spell slots and short/long-rest resources. Manual resources, hit dice, conditions, temporary HP and custom rules retain the existing sheet-button behavior. Rest changes increment sheet revisions and preserve coins, inventory and other sheet fields.

**Allow assigned characters to perform approved property downtime work** uses existing approved jobs, assignments, skills/checks, materials and presence permissions. Work is prorated over the existing 24-hour campaign-day unit; integer remainder tracking prevents repeated small advances losing labor. Hired contractors progress with elapsed time and the same budgets, material reservations and supervision rules. Without character downtime, travel/rest grants no character labor. Project stage completion retains the existing one-stage-per-settlement behavior; excess labor is not automatically carried into an unreviewed next stage. This is campaign time, with no wall-clock scheduler. All advances are DM-only, reviewed against a fresh economic state, journaled and retry-safe.

## Search and Library records

NPC records start with **Details & actions** collapsed. Expand an individual record to read its description, interact, configure it or manage linked blacksmith permissions. Its name and location remain visible; the name still opens the matching Library entry. Collapsing retains unsaved permission drafts. **Create non-party NPC** opens its editor above the records beside the creation control, and **Configure NPC** brings the same editor into view. Existing search, import, dialogue and visibility rules remain.

Data dropdowns include a search box; type a name or hierarchy words, then tap a result or use arrows and Enter. Escape cancels. Long result lists offer Show more, and every option remains searchable. NPC and imported monster screens retain their existing searches and now also provide searchable record pickers.

Map record names and NPC/source-reference links open the matching entry in Library, including its saved description, image, source pages, monster fields and warnings. Library has a record-type filter, full-text search and pagination. Related references open their own entries. Interact with this NPC opens that person; View saved map opens that map. Entries follow current campaign permissions, and source packs remain private to DMs.

## Individual characters and downtime

Open **Party → Character locations & downtime**, or select an NPC in **People & NPCs**. Search for a character, change **In party**, select an individual location (or **Unassigned / NPC list**), then **Save character placement**. Party members follow the party location; departed characters keep their own location. NPCs transfer under the same identity, retaining sheets, holdings, coins and history. The complete DM sheet directory includes departed characters and location NPCs. Maps group individual character/NPC icons at reviewed anchors and Library entries link their permitted sheets.

**Visible to players** hides or shows the record. **NPC sheet visible to players** independently controls read-only access to NPC sheets. These permissions are applied to current player room data, direct campaign-sheet reads, map/Library entries and character invitations. Existing campaign chat, previously shared information, saved account profiles and historical session archives retain their existing purpose and permissions.

Enter a named action, its location and 1–3650 campaign days, then **Start character downtime**. The character leaves active party counts and encounter planning while retaining all assets. Time passes only through DM-approved **Downtime** or **Session Time**, with completion listed in those previews. At the exact finishing campaign hour the prior party membership/location returns once; current visibility choices stay in effect. **Cancel character downtime & restore placement** ends an action without advancing time. During an active action the DM may change visibility; cancel it before moving the character. Pending campaign downtime must be approved/cancelled before changing placements or actions.

Descriptions, training results, rewards and special game rules remain DM-managed; these actions do not mint coins/items or silently apply character rules. Existing property recipes/jobs still manage labor, materials, wages and production; assigned characters contribute at their own reviewed location.

## Split the party

Owner decisions (2026-10-25, mockups approved as shown). Party members can stay in the party while travelling in **groups** at different places; groups merge back later. Leaving the party (the placement form above) is unchanged and is a different action.

**Model (tabletop protocol 10, optional fields only; no D1 migration).** The **main group** (letter A) keeps today's party fields: `market.currentLocationId` and `world.partyPosition`. A character in the party without `groupId` is in the main group, so a campaign that was never split reads byte-for-byte as before. Other groups live in `world.groups` (`name`, `colour` green/blue/amber/plum/teal/red, `letter` B–F, `locationId` or a road `position`, `hidden`, `status` active/merged; merged groups stay as history). `world.mainGroup` labels the main group while split; `world.groupRequests` holds players' move requests. Positions carry `groupId`, downtime `returnGroupId`, aboard records `returnGroupId`, journeys `groupId`. At most six groups (main plus five), each with its own colour and letter. Every group other than main keeps at least one character (characters on downtime or aboard alone count for the group they return to).

**Commands** (shared engine `party-groups-command.ts`; offline runs the same code through `executeLocalCommand`). None moves money. DM only: `party-split`, `party-group-edit` (name, colour, hide), `party-group-assign` (move one character between groups), `party-merge` (every group at the same place, or one inside the other; none on the road or on a journey), `party-location` / `party-map-position` with `groupId` (move a group at once: no time, nothing charged). Each compares `partyGroupsFingerprint` and is refused while campaign downtime is pending. Players: `party-group-request` for a group their visible character is in (one waiting request per group), `party-group-request-withdraw`; the DM answers with `party-group-request-review` (approve moves the group once; deny keeps an optional reason shown to the player).

**Shared while split.** Membership is unchanged: everyone stays `inParty`, so party balances, companion funds, the treasure pool, fairness, coin splits and Give work exactly as before, across groups, and party funds belong to every group. Only location-based things follow each group: `characterLocation` reads the character's group, so services, courier letters and beneficiaries are per group; buying, selling, property listings, NPC talk and barter, exchanges and aboard trading check the acting character's group (`actingGroups`); party funds act from the seat's groups. The DM's tools have no presence check, as before.

**Privacy.** Players see every group's name, colour and place, unless the DM hides a group: players with no character in it see it as "Elsewhere" (no location or map position, and its place stays out of the public events). Hidden characters are never shown as group members to players. Players see only their own move requests, and a denial reason only when it is shared. Each player's shops, NPCs, listings and exchanges are those at their own groups' places.

**Older apps (protocol 9 and below)** receive the table without groups (also inside archived reports) and see every party member at the main group's place. The server refuses their actions for a character outside the main group with "The party is split into groups. Update Lootsplitter to act for <name>." Their whole-journal writes keep the stored groups; pending drafts with group commands ask them to finish on the updated website; account backups with groups are restored on the updated website.

Journeys still move the main group only in this phase (`journeyTravellers` counts the main group; the journey quote names characters "with <group>" as staying behind). Downtime: a character returns to the group it left, the group that merged it, or the main group. Boarding a ship alone still leaves the party; landing where a group is rejoins it (its own group first).

## Development and verification rules

Moved verbatim from `docs/CODING-MANUAL.md` on 2026-10-21 so each feature's rules live with the feature. They still apply whenever this area changes.

### Multiple app windows and campaign context

Use `activeCampaignId()` from `campaign-context.ts` for runtime campaign identity, never the device-wide `quire.campaign.v1` default. The access gate pins each running document before opening its providers. Intentional selection goes through `selectWindowCampaign`; legacy default/deletion recovery remains compatible. Scope capture, database access, cloud sessions, seat/owner checks, recovery and audio must agree. New browser windows inherit only the existing session-storage context and reconnect normally; never put seat/account credentials in URLs or broadcast campaign content. Remove `opener` before navigating to the approved internal destination. Preserve fresh-document title startup and all draft guards.

Workspace events are invalidations, not replicated data or authority. Refresh relevant same-campaign views from canonical storage/server; account events clear cached identity before rechecking. Never broadcast from a passive reload, which would create an invalidation loop. Shared sync queues under its existing cross-window Web Lock with a bounded wait and captured-campaign recheck. Atomic IndexedDB commands, server permissions, stale revisions and retry receipts remain mandatory. Character/encounter drafts must remain untouched until explicit save/reload. Run the full finance audit (real tabs, popups, concurrent requests, per-window campaign isolation), ships audit (guest companion/privacy/reconnect/close), character/encounter/navigation/Help preservation and both builds in development and immutable Worker gates. No new migration, dependency, backend service or native APK distribution is required.

### TV and player display (October 16, 2026)

DMs can open Player display from the header, Maps or the current campaign encounter. A separate window/tab shows only an explicitly projected shared map, selected combatants and optional confirmed loot awards. Fullscreen, rotation, fit/zoom/pan and measured tile-pixel calibration support TVs and map cases. HDMI/extended desktop uses OS window placement; wireless use relies on the browser’s Cast tab support. This adds no public receiver link or remote seat. The viewer mounts no campaign/account providers, clears copied session credentials, receives only strict-schema presentation frames in memory and clears on blanking/controller loss. Secret notes, DM-only map records, unrevealed combatants and unawarded loot are excluded. Awards still use the existing atomic transaction and receipt. Player Help and DM Help cover the distinct workflows. Native Android navigation, all six main tabs and prior maps/encounters/loot remain. Verification extends the complete development/immutable Worker map audit rather than replacing original scenarios; see `docs/audit/2026-10-16-multi-window.md`.
